# Judge Demo

Everything in the demo runs the application's real workflows on synthetic data. No response is pre-scripted in the UI.

## Accounts (only when `DEMO_MODE_ENABLED=true`)

| Login page button | Account | Purpose |
|---|---|---|
| **Enter Judge Demo as Rahul →** | synthetic worker Rahul Kumar (phone 9000000001) | drives the demo, asks the agent |
| **Open Investigator Console (admin)** | admin (9000000009) | cross-worker console, memory activity, audit |
| (API: `POST /auth/demo-login {"as":"second-worker"}`) | synthetic worker Asha Reddy (9000000002) | isolation checks: own data, own memory bank |

Normal OTP login still works. In development, the OTP is shown on screen.

## Steps (`/demo`)

| # | Button | API | What really happens |
|---|---|---|---|
| 1 | Reset demo | `POST /api/v1/demo/reset` | deletes the synthetic workers' Hindsight banks and records; recreates the profiles; seeds Asha's separate history and memories |
| 2 | Load history & learn patterns | `POST /demo/steps/load-history` | 35 sessions (27 Apr–18 Jun) ingested → anomaly engine → platform notice retained → 7 pattern memories retained |
| 3 | Ask "What do I normally earn on Friday evenings?" | `POST /me/agent/ask` | baseline tool + Hindsight recall |
| 4 | Introduce first anomaly | `POST /demo/steps/first-anomaly` | 19 Jun ingested → `INVESTIGATION_RECOMMENDED` → `historical_anomaly` retained |
| 5 | Ask "Why did my earnings drop?" | `/me/agent/ask` | full analysis + recall; answer offers **Create investigation** |
| 6 | Open investigation / agent offer | `POST /demo/steps/open-first-investigation` or `POST /me/investigations` | ES-2026-0001 with evidence, findings, recalled memory; finding retained |
| 7 | Resolve with platform clarification | `POST /demo/steps/resolve-first-investigation` | 20–24 Jun ingested; report generated; outcome saved → **outcome retained** |
| 8 | Jump to Fri 14 Aug | `POST /demo/steps/time-jump` | 25 Jun–14 Aug ingested (17 Jul outage dip, 10 Aug zone notice, 14 Aug anomaly); patterns re-learned |
| 9 | Ask "Why did my earnings drop again?" | `/me/agent/ask` | **the previous outcome is recalled**; actions reordered; refined inference |
| 10 | Open comparison | `POST /me/agent/compare` | the same question with current-only, history-only and history + Hindsight |
| 11 | Open investigation for 14 Aug | `POST /me/investigations` | ES-2026-0002 cites the recalled outcome + previous case; generate the report |

**Fast-forward to step 9** runs steps 1–8 in sequence. From the command line:

- `npm run demo:seed`: steps 1–2
- `npm run demo:scenario`: steps 1–8

Only synthetic profiles are touched. Reset refuses to delete a non-synthetic profile.

## Synthetic story

| Date | Record |
|---|---|
| 27 Apr – 18 Jun | Friday 18–23 shifts: 22–26 orders, ₹935–₹1,055 net, Evening Peak Bonus ₹250 every time |
| 15 Jun | Notice: bonus eligibility terms updated (no details) |
| 19 Jun | 24 orders, acceptance 85.7%, bonus ₹0 ("Not eligible under current programme terms"), net ₹759 |
| 24 Jun | Synthetic clarification: acceptance threshold 80% → 90% from 15 Jun |
| 17 Jul | Dispatch disruption, 15 orders, net ₹479 (explained by volume) |
| 10 Aug | Notice: bonus zone map revised (no details) |
| 14 Aug | 25 orders, acceptance 92.6%, 9 orders in Zone B, bonus ₹0 ("Not eligible"), net ₹807 |

The dataset is generated by `apps/api/src/demo/dataset.js` with a seeded PRNG per date. It is identical on every machine; a unit test asserts this. It describes no real company, policy or person.

## If something goes wrong

- The badge says **Hindsight Memory · Unavailable**: start Hindsight and run `npm run hindsight:check`. The demo still runs, with memory steps shown as unavailable.
- "A demo step is already running": wait; steps are serialised.
- To start over, use **Reset demo**.
